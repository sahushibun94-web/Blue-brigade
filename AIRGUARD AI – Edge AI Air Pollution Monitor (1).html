    Functional block diagram

    PMS5003 (UART)BME688 (I²C)BME280 (I²C)CO module + ADS1115 (I²C)→UNO Q MCU (STM32U585): sampling, median filter, RH correction, LED/buzzer⇄ Bridge ⇄UNO Q MPU (Linux): features → TinyML classifier + trend model → alert rules → SQLite→Wi-Fi hotspot dashboard (local only)

    MCU keeps real-time I/O and the safety alerts running; MPU does inference and serves the dashboard. Check current Arduino App Lab docs for the exact MCU↔MPU bridge API and pin names.

    Edge AI processing workflow

    1. Sample sensors (PM duty-cycled, e.g. 30 s ON per minute); median-filter spikes.
    2. Apply humidity correction to PM; apply calibration coefficients.
    3. Compute AQI (CPCB NAQI breakpoints for PM2.5/PM10; CO/VOC shown as readings).
    4. Build window features: mean, slope, PM2.5/PM10 ratio, CO, VOC index, time of day.
    5. Trend model (linear/ridge regression or small GRU) → +15/+30 min AQI.
    6. TinyML source classifier (random forest / small NN, trained on labeled field + replay data) → class probabilities; show confidence, never certainty.
    7. Rules with hysteresis create alerts and situation-specific advice.
    8. Log readings and predictions to local SQLite; serve dashboard over local Wi-Fi. No personal data, no tracking.

    Implementation plan

    • Hardware (wk 1–2): breadboard, then PCB/perfboard; enclosure with rain-shielded inlets and fan airflow; fit sensors away from heat.
    • Firmware (wk 2–3): MCU drivers, sampling scheduler, watchdog, LED/buzzer logic; MPU service for storage, inference, web dashboard.
    • AI model (wk 3–5): collect labeled windows (traffic, burning, dust, background), train/validate with a held-out location, quantize to TFLite/ONNX, measure latency and RAM.
    • Calibration (wk 4–5): co-locate with a reference monitor for several days, fit PM correction (incl. RH); CO zero/span; re-check drift periodically. Until done, show readings as "uncalibrated".
    • Testing (wk 5–6): outage test, 72 h soak, rain/heat test, power logging, alert false-alarm review.

    Known limitations

    • Low-cost PM sensors are less accurate at high humidity and for very fine or very coarse particles.
    • Source classification may be wrong and varies by site; validate before relying on it.
    • The classifier on this page is a rule-based stand-in for the trained model.
